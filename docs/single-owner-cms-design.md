# 單人網站管理後臺設計

狀態：依使用者選定的第一方案與單人管理需求整理，待確認細節後實作。

## 目標與選擇

以 Decap CMS 搭配 Decap Turbo 免費方案，提供單一擁有者的內容管理介面。正式網站維持 GitHub Pages 與現有網址。相較客製後臺可減少登入及編輯器維護；相較改用 WordPress 可保留現有路由與部署平台。

方案依目前官方資料提供一個網站、一位使用者。免費額度或條款變更時需重新評估，不承諾第三方永遠維持現行條件。不建立付費訂閱。

## 管理入口及權限

預定入口為 https://coolokey.github.io/dsjh-math/admin/ 。入口網址公開可見，但只有擁有者登入後才能編輯；不開放其他老師註冊或邀請。透過 Turbo 的正式登入流程認證，GitHub App 僅授權此網站儲存庫。不得把存取金鑰、密碼或 OAuth 秘密寫入靜態頁面。

需要擁有者完成服務註冊、條款接受及 GitHub App 授權；代理可先完成程式及設定說明，但不能宣稱未驗證的登入或儲存已可用。

## 第一版功能

- 公告：日期、標題、內文、連結，新增、修改、刪除及排序。
- 網頁：標題、內文、檔案、相片，以及新增、修改、隱藏與刪除。
- 分類：上層分類與順序，以既有名稱及階層初始化；檢查不存在的上層、重複路徑及循環。
- 教材與照片：上傳並引用網站內的 PDF、Word、圖片；刪除頁面不自動刪除可能共用的檔案。
- 草稿、內容預覽與發布；預覽先提供內容預覽，不能把它宣稱為完整正式網站預覽。
- 發布進度提供部署結果連結；如 CMS 原生部署偵測不能直接對應自訂工作流程，明確提供 GitHub Actions 狀態入口。

以繁體中文欄位與操作說明為主。編輯器採文字及媒體編輯，不提供任意拖拉整站版面的建站工具。

## 內容來源及搬移策略

目前 scripts/build.py 依賴未追蹤的 backup/；必須先改為儲存庫內可獨立建置的正式內容來源。既有 HTML 內容中有表格、相簿及嵌入，不能直接轉為 Markdown 而犧牲原文或結構。

實作時建立有版本紀錄的頁面中繼資料及內容檔，既有複雜區塊保留為受支援的 HTML 或結構化區塊，再由共用版型產生。必須實證編輯器載入、修改、儲存後仍保留原表格、相簿順序、文件及嵌入；不支援的舊區塊保留並提供清楚的管理方式，不得默默移除。

既有頁面沿用固定 ID 及檔名；改標題不改網址。新增頁面產生穩定識別碼。隱藏頁面不列入選單，仍可直接讀取，不屬於私密權限功能。正式內容與草稿可能存於公開儲存庫，草稿僅代表尚未部署，不適合存放機密資料。

首頁、共用頁首及頁尾等必要頁面禁止刪除；刪除有子項的分類前需先移動子項。首頁保留專用內容模型，公告與既有好文內容均須保留。

## 發布與失敗處理

後臺儲存草稿至編輯分支；發布後合併正式內容並觸發 GitHub Actions，完成驗證、建置及 GitHub Pages 部署。自動流程取代目前需人工 subtree push 的流程。

建置錯誤時不部署失敗產物，正式網站維持上一個成功版本。頁面刪除、導覽及附件引用錯誤應在部署前攔截。保留 Git 歷史，以還原提交並重新部署的方式恢復誤改內容。

## 驗收

1. 乾淨環境不含 backup/ 也能建置；舊內容、附件及相簿基準檢查通過。
2. 未登入無法寫入，登入者只有擁有者；秘密未出現在公開輸出或儲存庫。
3. 實際新增測試頁、草稿預覽、發布、修改、隱藏、刪除與還原，並檢查正式網址結果。
4. 實際上傳一份文件與圖片，確認引用與發布；測試共用檔案不因刪頁遺失。
5. 桌機與手機檢查管理入口及前臺；原分類、網址及已搬移素材維持完整。
6. 留下繁體中文操作指南與實測發布紀錄；未完成帳號授權時明列待辦，不標示整體完成。
