## 五、日常操作手冊

### 5.1 登入與找頁面

1. 開啟管理後臺，按 **Login with Turbo**。
2. 以本人已授權的帳號登入；若工作階段過期，重新登入即可，已成功儲存的草稿仍在 GitHub。
3. 左側「首頁」→「首頁內容」用於首頁公告、原有首頁內容與主視覺。
4. 左側「網頁與分類」用於其他頁面；選取既有頁面或按「＋網頁」新增。
5. 後臺列表中的固定識別碼屬網址依據，保留原值，不需自行修改。

### 5.2 新增首頁公告

1. 「首頁」→「首頁內容」→「新增公告」→新增一筆。
2. 填「公告日期」「公告標題」；「公告內容」與「公告連結」可依需要填寫。
3. 日期欄位用西元，例如 `2026-10-30`，前臺顯示為 `1151030`。
4. 多則新公告依列表順序呈現，可拖曳把最新的一筆放在最上方；不是自動依日期重新排序。
5. 新公告會位於「最新消息」標題下方、原有 `1150312` 公告之前。
6. 儲存後按 5.7 節的流程發布，到前臺確認標題位置及連結。

例如連至新行事曆的公告連結可填：

```text
https://coolokey.github.io/dsjh-math/page-950890031291555289.html
```

### 5.3 修改首頁「網站近期更新日期」

1. 「首頁」→「首頁內容」→「原有網頁內容」。
2. 在視覺編輯區找到「最新消息」旁的 `網站近期更新日期`。
3. 直接改成所需民國日期，例如 `115/10/30`。
4. 儲存、發布、等待部署成功，再重新整理前臺。

此日期與「新增公告」的公告日期是兩個獨立資料，不會互相自動同步。

### 5.4 在領域行事曆增加新學期

1. 「網頁與分類」→「領域行事曆」。
2. 「新增內容位置」選 **放在原有內容上方**。
3. 「新增內容區塊」加入「文字」，填學年度／學期標題；需要標題層級時在文字編輯器選標題。
4. 再加入「文件」，按「選擇一個檔案」→「上傳新內容」，上傳 PDF 後選取。
5. 填「文件說明」，例如「開啟／下載 115 學年度第 1 學期行事曆」。
6. 如有七、八、九年級不同文件，可依序增加文字與文件區塊。
7. 同一批新增區塊依列表順序顯示，可拖曳調整；上方／下方設定是相對於整份「原有網頁內容」，不是任意插入舊內容中的某一列。
8. 發布後確認最新標題位於舊學年度上方，文件連結與「展開文件預覽」均存在。

本機上傳的 PDF 文件會自動產生預設收合的預覽按鈕，展開時才載入。Word 等其他格式維持下載連結；外部 PDF 連結不自動轉成此本機預覽。

### 5.5 新增頁面與分類

1. 「網頁與分類」→「＋網頁」，填標題。
2. 上層分類留空代表主選單；選既有頂層項目則成為第二層子頁。
3. 第一版只支援兩層選單，不要把子頁再設為別人的父分類。
4. 「排序」數字較小的排在前面。相同數字會再依 ID 排序，建議採 `10、20、30` 等數字預留插入空間。
5. 以「原有網頁內容」或「新增內容區塊」編輯。新頁面通常以區塊新增較容易維護。
6. 固定 ID 在新增時自動產生；正式網址為 `page-固定ID.html`。
7. 儲存與發布後，再檢查選單、麵包屑與前臺連結。

「原外部連結頁面」是歷史中繼資料旗標，**勾選它不會自動建立外部網址或轉址**；外部目的地仍要在內文建立正常連結。

### 5.6 修改、隱藏、刪除與檔案管理

- 修改舊資料：在「原有網頁內容」直接改文字。表格、相簿與舊 PDF 結構需保留；「進階 HTML」僅供熟悉標記者使用。
- 隱藏頁面：勾選「不列入導覽」，仍可透過原網址讀取，不能用作私密資料保護。
- 隱藏分類：先隱藏或移走子頁，避免有可見子頁掛在隱藏分類下。
- 刪除頁面：先移動子頁、移除其他頁面指向它的連結，再執行刪除及發布；否則建置可能攔截。
- 首頁禁止刪除，必要系統檔與素材目錄不要用檔案工具整批刪除。
- 媒體庫刪檔前，先確認沒有其他頁面共用。刪除頁面不會自動刪除共用附件。
- 大型影片使用 YouTube 等外部服務，避免持續把大型影片放入 Git 儲存庫。
- 影片區塊目前接受標準 YouTube `watch?v=` 或 `youtu.be/` 分享網址；不是通用影片託管平台。

### 5.7 儲存、審核與發布

1. 編輯後按「儲存」。這只代表資料已保存，不代表已上線。
2. 開啟頂端「作業流程」，在「草稿」欄找到項目。
3. 開啟項目，把「狀態：草稿」改成「預備發布」。
4. 按「發布」→「立即發布」。
5. 若出現瀏覽器的確認視窗，閱讀後按「確定」。未完成確認，合併動作可能尚未送出。
6. 等待後臺顯示 **Deployed** 或發布紀錄顯示 **Live**。
7. 到正式網站確認結果。若後臺仍顯示 Building，先查看 Actions，狀態同步可能稍有延遲。

草稿實際對應 `cms/…` 分支及 Pull Request；正式發布會合併到 `main`，之後由 Actions 建置與部署。正常日常更新不需手動使用 Git，也不需手動執行 subtree 指令。

```powershell
python -m pip install -r requirements.txt
```

若工作目錄已有變更或有其他維護者的修改，先確認內容，不要使用 `git reset --hard` 覆蓋。

### 7.2 日常測試與建置

```powershell
python -m unittest discover -s tests -p test_content.py -v
python -m unittest discover -s tests -p test_cms_release.py -v
node --test tests/editor.test.cjs tests/bootstrap.test.cjs
python scripts/build.py
```

建置使用 `content/`、版型與 `site/assets/`，不需 `backup/`。會先驗證來源，再產生輸出；有不存在的父分類、循環、第三層分類、不安全 HTML 或缺少本機附件時會失敗。

若只要檢查輸出、不想改動已追蹤的 `site/*.html`：

```powershell
python scripts/build.py --out qa/handover-site
```

此暫存輸出不會複製全部素材，不能直接把它當成獨立完整網站備份。

### 7.3 技術修改發布

1. 同步遠端 `main`，確認沒有未處理的 CMS 草稿或他人修改。
2. 技術修改採 `codex/…` 等專用分支，完成適當測試及檢查差異。
3. 經授權後合併到 `main` 並推送；Actions 自動測試、建置、上傳 artifact 與部署。
4. 等待對應 commit 的成功執行，到正式網址測試。

```powershell
gh run list --repo coolokey/dsjh-math --workflow pages.yml --limit 5
gh pr list --repo coolokey/dsjh-math --state open
gh api repos/coolokey/dsjh-math/pages --jq '{build_type,html_url}'
```

PR 事件僅建置驗證，不部署。`main` 的推送與手動 workflow_dispatch 可發布。建置失敗時，既有正式網站通常維持上一次成功產物；先修正失敗，不要把 failed 當作已發布。

`gh-pages` 是早期 subtree 發布保留分支，現已停止作為正常發布來源。不要在日常流程執行 `git subtree push --prefix site origin gh-pages`；這不會取代目前 Actions 的正式流程。

### 7.4 正式內容比對

`scripts/verify_live.py` 會下載頁面、後臺檔案、PDF／Word 與相片樣本，比對本機位元組。比較文字檔時會統一換行；**不是逐一檢查全部圖片或所有外站連結**。

此腳本另需 requests；requirements.txt 的日常建置依賴未包含它。執行前務必同步遠端，從最新內容重新建置，並等待相同來源的部署完成：

```powershell
git pull --ff-only
python scripts/build.py
python -m pip install requests
python scripts/verify_live.py
```

腳本將 `origin/main` 視為比對版本；若最新提交是只更新文件、略過 CI 的提交，報告的 commit 不一定等於實際部署的來源。此時必須人工核對 Actions 的 head SHA，不可只看報告欄位。

這個腳本會覆寫 `docs/deployment-verification.json`。驗證結果若要保存或交付，先留存舊紀錄並清楚標明這次時間與部署來源。

## 九、備份與還原

### 9.1 必須保存的三類資料

1. **正式來源與素材：** Git 歷史、`content/`、`site/assets/`、`scripts/`、`templates/`、`site/admin/`、工作流程與測試。
2. **本機歷史備份：** `backup/` 與需要保存的 `qa/` 截圖／報告。它們不在 Git，重新 clone 不會取回。
3. **服務設定與復原資料：** GitHub／Turbo 擁有者、Site ID、repo 範圍、復原聯絡方式；密碼與復原碼另行安全保存。

建議每次大量更新後做一次備份，並至少維持一份不在同一台電腦或同一顆硬碟上的副本。

### 9.2 Git 備份範例

在自行選定、尚未存在的備份位置執行，以下命令不會替你備份 ignored 的本機資料：

```powershell
git clone --mirror https://github.com/coolokey/dsjh-math.git dsjh-math-mirror.git
```

另以檔案總管複製整個 `F:\1151029---webbly` 到指定安全位置，並確認其中包含 `backup/` 與 `qa/`。不要只保留一份可下載的網站 HTML 當成完整備份，也不要把包含本機擷取資料的整個資料夾隨意公開上傳。

### 9.3 復原個別誤改

1. 找到誤改的提交，查看差異並確認影響範圍。
2. 先保留現況與未發布草稿，避免還原時覆蓋其他人的修改。
3. 優先還原個別檔案或使用 `git revert` 產生可追蹤的還原提交，不強制改寫歷史。
4. 若是 merge commit，需先判斷 parent，不能直接照抄一般 revert 命令。
5. 重新測試並部署，到前臺確認。

```powershell
git log --oneline -- content/home.json
git log --oneline -- content/pages/950890031291555289.json
```

媒體檔若仍存在 Git 歷史，可取回後重新發布；若秘密曾進入 Git，刪掉最新版檔案不代表歷史秘密已清除，須先撤銷／輪換秘密，再由有經驗者處理歷史。

### 9.4 平台或登入故障時

- Turbo 故障：GitHub 上的內容仍在，可由有權限的技術維護者直接修改正式來源並走 Actions 發布。
- 本機電腦故障：可重新 clone 取回已追蹤內容；ignored 的備份需由另存副本復原。
- GitHub Pages 故障：保留完整來源與素材，可在其他靜態主機重建，但需另外調整網址基底、CMS 管理 origin 及所有必要連結。
- 改回舊 `gh-pages` 發布只適用於緊急暫時復原，內容會回到較舊狀態；啟用前先確認分支內容，正常日常發布仍以 Actions 為準。

## 十、常見問題排查表

| 問題 | 優先確認 | 處理方式 |
|---|---|---|
| 已儲存但前臺沒變 | 草稿是否仍在作業流程 | 設預備發布、立即發布並完成確認，再等部署 |
| 標題存在但位置不對 | 選的是新公告、區塊或原有 HTML | 首頁用新增公告；內頁區塊設定上方／下方，並確認排序 |
| 最新行事曆在最下方 | blocks_position 是否為 after | 後臺選「放在原有內容上方」，再次儲存發布 |
| 新 PDF 沒預覽按鈕 | 是否選文件區塊、本機 PDF | 本機 PDF 自動預覽；只貼網址、Word 或外部 PDF 不屬相同情況 |
| 舊畫面仍存在 | 部署版本、快取與網址 | 等成功後重新整理，可暫加 `?v=提交短碼`；版本參數不會代替部署 |
| 後臺顯示 Building 很久 | Actions 是否已成功 | 看對應 commit；可開 Deploys 的 Refresh，等狀態同步 |
| 工作階段過期 | Session expired 提示 | 用正式 Turbo 登入重新登入，不要提供 token 或密碼給協助者 |
| 發布操作停住 | 是否有原生確認視窗 | 查看目前及其他後臺分頁，處理確認視窗後再看 PR 是否已合併，勿盲目重按 |
| 進階 HTML 顯示內容被清理 | 是否含 script、事件、表單或不安全 URL | 使用受支援區塊與安全標記；不關閉安全驗證硬推 |
| 建置缺附件 | 素材是否確實進入同一提交／分支 | 補上檔案或修正引用，不以刪除驗證規則解決 |
| 無法刪除／隱藏分類 | 子頁、其他頁面的引用 | 先搬移子頁並修正連結，再操作 |
| 前臺更新日期仍是舊的 | 是否只新增公告 | 該日期是固定文字，需另外修改首頁原有內容 |
| 將新公告拖曳後順序沒變 | 改的是哪一份草稿、是否完成發布 | 對照最新 main 與部署，列表順序不等於日期自動排序 |

如由技術維護者代替 CMS 合併 PR，應先確認使用者授權、建置結果及當前 PR 狀態，並在紀錄中說明實際發布方法；不能把替代操作宣稱為已測過所有原生 UI 步驟。

## 十一、已知限制與服務差異

1. 網站是靜態站，沒有學生帳號、成績資料庫或私密檔案權限。
2. Git 儲存庫公開；草稿分支與歷史也可能可見。不要放學生個資、未公開資料、密碼或存取權杖。
3. 後臺提供內容編輯與區塊管理，不是 Weebly 的任意拖拉整站版面工具。
4. 第一版分類只支援兩層，沒有多角色共同審核流程的客製化管理。
5. 舊 HTML 中保留的複雜表格與相簿，仍需小心編輯，任意改 HTML 有破壞結構的風險。
6. 原 Weebly 留言表單已停用，站內搜尋未移植。
7. 外部相簿、YouTube、Google Sites 等仍依賴原服務；歷史連結檢查不是永久可用保證。
8. 原紀錄為 18 個確定失效的外部連結、22 處引用已停用；其他逾時／拒絕存取項目未一律視為失效。細節見 skipped-links.json 與 migration-report.md。
9. 後臺預覽僅協助看內容，並非保證提供每份草稿的完整獨立公開預覽站；發布後仍需前臺確認。
10. 管理入口可公開，真正寫入權限由 Turbo 與 GitHub 授權控制；本次未重新做滲透測試或獨立資安稽核。
11. Free 方案與外部服務條款可能變更；交接與加人前必須重新查閱。
12. 舊 `tests/baseline.json` 保留的原文，在使用者合法改寫或刪除後，歷史比較可能不再通過；日常 CI 不強制所有原文永遠不變。
